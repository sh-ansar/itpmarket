# Аудит данных Kaspi и логики сопоставления

## Исходное состояние

В локальной базе находится **890** активных позиций Kaspi. Подробные карточки получены для всего каталога; среднее число характеристик в одной карточке — **11.13**.

Старая аналитика распределяла позиции следующим образом:

```
{
  "ANALOG_LOSE": 180,
  "ANALOG_WIN": 108,
  "NO_ACCEPTED_MATCH": 566,
  "ANALOG_TIE": 19,
  "ANALOG_NEAR": 17
}
```

Главная проблема заключалась не в сборе карточек, а в интерпретации совпадений. В таблице `market_candidates` было **559** автоматически принятых совпадений. Консервативная проверка названий показывает около **342** межбрендовых совпадений (61,2%). Поэтому одинаковые размер, сезон и индексы иногда ошибочно превращали товар другого бренда и ценового класса в «аналог».

## Проверенная ошибочная позиция

Для `Continental CrossContact ATR 265/60 R18 110T` старая модель принимала `Sailun Terramax A/T 265/60 R18 110T` стоимостью 54 500 ₸ как допустимый аналог и сравнивала его с ценой Unityre 137 300 ₸. Разница 82 800 ₸ и 151,9% математически была рассчитана верно, но бизнес-смысл был неверным: премиальный Continental сравнивался с эконом-брендом Sailun на основании только технических параметров.

После изменения правил позиция получает статус:

```
{
  "price_status": "REVIEW_REQUIRED",
  "status_label": "Требует проверки сопоставления",
  "reference_type": "NONE",
  "reference_count": 0,
  "market_median_price_kzt": null,
  "difference_kzt": null,
  "potential_margin_per_unit_kzt": 0.0
}
```

Она больше не формирует ценовой риск, рыночную медиану или «упущенную выгоду» без подтверждённого сопоставимого сегмента.

## Новая логика

1. **Точный товар** — одинаковый бренд, близкая модель и совместимые технические параметры. Для расчёта требуется не менее двух подтверждённых ценовых наблюдений.
2. **Рыночный сегмент** — совместимые технические параметры и одинаковый ценовой класс бренда. Для статистики требуется не менее трёх карточек.
3. **Требует проверки** — технически похожий товар другого класса, неполная карточка или единственный кандидат.
4. Явные ценовые выбросы удаляются по межквартильному диапазону при достаточном размере выборки.
5. Потенциал маржи рассчитывается только для явно недооценённых позиций и ориентируется на нижний квартиль, а не на случайную максимальную цену.

Распределение после финального консервативного пересчёта:

```
{
  "REVIEW_REQUIRED": 611,
  "INSUFFICIENT_DATA": 235,
  "EXACT_LOWEST": 12,
  "EXACT_HIGHEST": 4,
  "EXACT_COMPETITIVE": 4,
  "SEGMENT_LOWEST": 4,
  "SEGMENT_BELOW": 1,
  "SEGMENT_IN_MARKET": 12,
  "SEGMENT_ABOVE": 1,
  "SEGMENT_HIGHEST": 6
}
```

Рост числа позиций «Требует проверки» является ожидаемым: система перестала выдавать ложную уверенность там, где данных недостаточно.


## Воспроизводимость расчёта

В старой вспомогательной логике резервное название модели формировалось из множества токенов. Порядок элементов множества зависит от `PYTHONHASHSEED`, поэтому часть пограничных сопоставлений могла менять статус между отдельными запусками приложения. В версии 3.0.0 токены модели сохраняются в исходном порядке названия. Распределение статусов проверено в независимых процессах Python с разными hash seed и остаётся одинаковым.

## Исправление характеристик

Поле `specifications_json` в базе является списком объектов вида `name/value/section`. Старый интерфейс обрабатывал список через `Object.entries`, поэтому показывал исходные JSON-объекты. В новой версии список нормализуется на сервере и отображается как пары «Характеристика — Значение».

## Ограничения MVP

- Ozon хранит цены в RUB; пользовательский курс RUB/KZT задаётся в настройках и не заменяет официальный бухгалтерский курс.
- «Потенциал маржи за месяц» зависит от установленного планового количества продаж. Без объёма отображается только потенциал на единицу.
- Позиции со статусом «Требует проверки» не участвуют в агрегатах риска и выгоды.
- Полный промышленный запуск сборщиков требует существующих профилей Kaspi/Chrome, которые намеренно не включены в архив.
