# Архитектура Spyon 3.0.0

## Назначение

MVP объединяет данные Kaspi и Ozon в одном интерфейсе, не смешивая код сборщиков. Каждый источник сохраняет собственные сессии, правила доступа и сырой формат, а веб-приложение формирует единое аналитическое представление.

## Контуры системы

```text
Kaspi Collector ──> unityre_kaspi.db ─┐
                                      ├─> DataService ─> Matching & Pricing ─> Flask API ─> Web UI
Ozon Collector ───> ozon_registry.db ─┘
```

### Kaspi Collector

Существующие рабочие сценарии сохранены:

- синхронизация каталога Unityre;
- обновление собственных цен;
- поиск карточек рынка;
- проверка характеристик;
- обновление предложений продавцов;
- повтор ошибочных позиций.

Профиль Playwright не входит в поставку и создаётся локально.

### Ozon Collector

Сборщик 3.0 работает через одну Chrome-сессию на порту 9222:

- discovery сохраняет `article` и постоянные ссылки;
- enrich получает характеристики новых товаров;
- refresh обновляет цены по сохранённому реестру;
- SQLite checkpoint фиксируется после каждой карточки;
- ошибки и блокировки попадают в отдельную очередь.

### Аналитический слой

`market_intelligence.py` не изменяет исходные результаты сборщиков. Он формирует безопасное представление:

- точные товары;
- сопоставимый рыночный сегмент;
- кандидаты для проверки;
- минимум, нижний квартиль, медиану, верхний квартиль и максимум;
- ценовой ранг;
- потенциальную маржу на единицу и за месяц.

## Базы данных

### `data/unityre_kaspi.db`

Основная прикладная база:

- каталог Unityre;
- подробные карточки Kaspi;
- собственные цены;
- кандидаты и предложения продавцов;
- история цен;
- пользователи и события;
- персональные настройки;
- сформированные отчёты;
- будущие ручные подтверждения совпадений.

Новые таблицы:

- `app_user_preferences`;
- `market_match_overrides`;
- `app_market_links`.

### `collectors/ozon/data/ozon_registry.db`

Изолированный реестр Ozon:

- `products`;
- `offers`;
- `price_history`;
- `catalog_snapshots`;
- `crawl_queue`;
- `runs`.

## Структура каталогов

```text
ITP_Market_Intelligence_MVP_3.0.0/
├── app.py                     Flask API и запуск панели
├── data_service.py            объединённое представление Kaspi/Ozon
├── market_intelligence.py     сопоставление и ценовая аналитика
├── schema.py                  безопасные миграции прикладной БД
├── task_manager.py            фоновые процессы и журналы
├── auth_service.py            локальные пользователи
├── engine/                    рабочий Kaspi-контур и отчёты
├── collectors/
│   └── ozon/                  независимый Ozon Collector
├── static/                    стили, JavaScript, логотип
├── templates/                 интерфейс и авторизация
├── data/                      основная SQLite
├── output/                    HTML/CSV/JSON отчёты
├── logs/                      журналы операций
├── backups/                   резервные копии
└── docs/                      аудит и эксплуатационная документация
```

## Расширение после MVP

Архитектура допускает добавление:

- Wildberries, Satu, маркетплейсов Грузии и других источников;
- централизованного PostgreSQL вместо локальных SQLite;
- очереди задач Redis/RQ или RabbitMQ;
- ручной модерации сопоставлений;
- планировщика ежедневных операций;
- API обмена с ERP;
- авторизованного облачного развёртывания.

Для нового маркетплейса достаточно реализовать адаптер, который отдаёт нормализованные поля `platform`, `source_product_code`, `title`, `brand`, `model`, `size`, `seller`, `price`, `currency`, `product_url`, `collected_at`.
