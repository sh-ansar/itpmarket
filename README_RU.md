# ITP Market Intelligence 3.1.0

Локальный MVP для мониторинга цен Unityre на Kaspi и ведения отдельного реестра Ozon.

## Главное изменение 3.1.0

Основная аналитика Kaspi переведена в режим **exact-only**:

```text
одна карточка Kaspi
один product_code
разные продавцы внутри этой карточки
```

Похожие товары, другие бренды, другие модели и старые сегментные аналоги больше не участвуют в:

- минимальной, медианной и максимальной цене;
- определении позиции Unityre;
- ценовых рисках;
- расчёте потенциальной маржи;
- управленческих отчётах.

Ранее собранные кандидаты не удаляются. Они сохраняются в SQLite как архив, но имеют признак `legacy_candidates_used_in_analytics = false`.

## Новые операции Kaspi

```text
Синхронизация каталога
Обновление цен Unityre
Точные предложения всех продавцов
Обновить устаревшие точные цены
Повтор ошибок точных карточек
```

Операция «Точные предложения всех продавцов» открывает исходную карточку каждого товара Unityre и получает предложения всех продавцов этой же карточки. Checkpoint сохраняется после каждого товара.

## Первый запуск полной сборки

1. Распаковать проект в новую папку.
2. Не переносить старую `.venv`.
3. Перенести `.kaspi_profile` с рабочего компьютера.
4. При необходимости перенести `.playwright`.
5. Для сохранения текущих данных скопировать:
   - `data/unityre_kaspi.db`;
   - `collectors/ozon/data/ozon_registry.db`.
6. Запустить `CLEAN_INSTALL.bat`.
7. Запустить `SELF_TEST_MVP.bat`.
8. Запустить `START.bat`.

Панель:

```text
http://127.0.0.1:8765
```

Доступ внутри сети включается через `ALLOW_LAN_ACCESS.bat`. Сервер запускается на `0.0.0.0:8765`, при этом авторизация остаётся обязательной.

## Установка hotfix поверх 3.0.5

1. Остановить приложение через `STOP.bat`.
2. Распаковать hotfix в корень текущего проекта с заменой файлов.
3. Запустить `APPLY_3_1_0_HOTFIX.bat`.
4. Запустить `SELF_TEST_MVP.bat`.
5. Запустить `START.bat`.
6. В разделе «Товары» выполнить:

```text
Kaspi → Точные предложения всех продавцов → Весь каталог
```

`APPLY_3_1_0_HOTFIX.bat` сначала создаёт резервную копию базы в `backups/`, затем добавляет новые таблицы. Старые данные не удаляются.

## Запуск на сервере для демо

Windows Server:

```text
START_SERVER_DEMO.bat
```

Linux:

```bash
./install_server.sh
./start_server.sh
```

Сервер слушает `0.0.0.0:8765`, автоматическое открытие браузера отключено. Для живого запуска Kaspi-сборщика профиль `.kaspi_profile` и Playwright должны находиться именно на сервере. Для живого Ozon-сборщика на сервере должен быть запущен Chrome с remote debugging `9222` и активной VPN-сессией. Клиентам в сети нужен только веб-браузер.

## Ozon

Ozon остаётся независимым контуром:

```text
каталог продавца → дополнительные категории → SQLite-реестр → цены и характеристики
```

Ozon не смешивается с Kaspi по похожему названию. Мотокамеры, мотошины и автомобильные шины разделяются по типу товара. Межплатформенное автоматическое совпадение допускается только в дальнейшем по артикулу производителя либо по полному строгому набору характеристик.

## Полнота каталога

Система использует количество товаров, которое Kaspi сообщает во время последней синхронизации. Если длительный проход был остановлен, существующие товары не деактивируются, а интерфейс показывает неполное покрытие каталога.

## Отчёты

Операция «Сводный отчёт» создаёт:

- HTML для просмотра;
- CSV для аналитики;
- JSON для интеграции.

В отчёте указывается метод сопоставления `KASPI_PRODUCT_CODE`, число продавцов одной карточки и архивное количество старых кандидатов.
